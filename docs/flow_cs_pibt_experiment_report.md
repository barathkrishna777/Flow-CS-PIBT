# Flow-CS-PIBT Experiment and Ablation Report

Date: 2026-04-29

This document consolidates the main Flow-CS-PIBT experiments, ablations, custom
data studies, and evaluation results collected so far. It is written as a
report-building artifact: the tables and interpretations are meant to be reused
later in papers, presentations, advisor updates, and final experiment summaries.

## Executive Summary

The main contribution remains the **flow-vector / flow-only Flow-CS-PIBT
policy**: a rectified-flow GNN that predicts continuous 2D motion preferences
and then uses CS-PIBT as the collision shield. Across the experiments so far,
no learned variant from this ablation series has robustly beaten the flow-vector
model on the medium or full Rishi-style benchmark. The only model that remains
above it is the external SSIL classifier baseline.

The headline result from the flow-vector model is:

| Model | Eval Scale | Rows | Overall Success | Mean Agents At Goal | Runtime | Notes |
|---|---:|---:|---:|---:|---:|---|
| Flow-vector / flow-only best, earlier ablation anchor | Full Rishi-8 | 1850 | 64.05% | 92.32% | 31.34s | Reported in `FLOW_VS_SSIL_ABLATION_PLAN.md` |
| Flow-vector `wave9_compact_best` | Full Rishi-8 | 1850 | 64.59% | 91.93% | 31.34s | Local CSV: `evals/rishi_full_wave9_compact_best.csv` |
| SSIL classifier | Full Rishi-8 | 1850 | 66.43% | 95.69% | 18.96s | External reference baseline |

There are two flow-vector anchors in the current notes. The earlier ablation
plan records **64.05%** full eval for "Flow best"; the local CSV-backed
`wave9_compact_best` summary gives **64.59%** full eval. Both tell the same
story: the flow-only model is close to SSIL but still behind, and all attempted
hybrid/action-head/custom-data variants have not yet surpassed it at robust
scale.

The main gap is not broad failure. Flow-vector performance is very strong on
several held-out maps: Paris, den520d, empty-48, and random-64. The gap to SSIL
is concentrated in dense or structurally difficult cases, especially
`random-32-32-10` and `maze-128-128-2`.

## Benchmark Protocol

The main comparison uses the Rishi-style grid MAPF benchmark:

- 8 held-out maps:
  - `Paris_1_256`
  - `den312d`
  - `den520d`
  - `empty-48-48`
  - `maze-128-128-2`
  - `random-32-32-10`
  - `random-64-64-10`
  - `warehouse-10-20-10-2-1`
- CS-PIBT collision shield.
- Success metric: all agents reach their goals.
- Secondary metric: mean fraction of agents at goal.
- Time limit: `120` seconds.
- Max steps: `3x`.
- Default flow inference:
  - `--policy-type flow`
  - `--num-integration-steps 3`
  - `--consensus 3`
  - `--tau 0.3`
  - `--wait-thresh 0.25`
- For non-default model sizes, eval always needs matching:
  - `--hidden-dim <...>`
  - `--num-layers <...>`

Eval scales used throughout:

| Scale | Description | Typical Rows |
|---|---|---:|
| Quick | `--quick`; 1 scenario per map, selected agent counts | 23 rows in recent runs |
| Medium | `--max-scenario 5`; 5 scenarios per map, all feasible agent counts | 370 rows |
| Full | `--max-scenario 25`; full Rishi-style held-out benchmark | 1850 rows |

Quick eval was useful for smoke testing but was repeatedly misleading. Several
action-head variants looked excellent on quick eval and then regressed on medium.
Medium eval is the main decision gate for follow-up experiments; full eval should
only be run after a model beats or clearly improves on the flow-vector medium
baseline.

## Dataset and Expert Data

### Base Training Data

The base training set is the repository's preprocessed flow dataset:

```text
data/preprocessed
```

On Lambda, this directory was reported as:

| Directory | Count / Size |
|---|---:|
| `data/preprocessed` | 1,169,520 `.pt` files |
| `data/preprocessed` size | 283 GB |

The flow model is trained from expert trajectories generated by EECBS, then
preprocessed into per-sample PyG `.pt` graph records. Each `.pt` file is one
training sample, not one scenario, so the preprocessed dataset expands far beyond
the raw `.npz` trajectory size.

### Base Model Objective

`main_pys.train_flow` trains a rectified-flow model by default. The current CLI
default includes an auxiliary discrete action loss:

```text
--action-loss-weight 0.3
```

For a strict flow-only training control, we explicitly pass:

```text
--action-loss-weight 0.0
```

For evaluation, "flow-only" or "flow-vector" means:

```text
--policy-type flow
```

It does **not** use the learned action head at inference time.

The custom coordination data was introduced to test whether the gap on
coordination-heavy maps, especially `random-32-32-10`, comes from insufficient
dense coordination examples rather than from the flow objective itself.

## In-Distribution vs Out-of-Distribution Analysis

Strictly speaking, all Rishi-8 eval maps are held out from training for the
headline comparison. However, the maps are not equally far from the training
distribution. It is useful to separate them into topology-proximal cases and
OOD-stress cases.

For the main flow-vector policy, topology-proximal/easier cases are:

- `Paris_1_256`: large city map, strong structural guidance.
- `den520d`: large game map, very high success.
- `empty-48-48`: open map, generally easy but sensitive to density.
- `random-64-64-10`: random obstacle map at larger scale, less cramped than
  `random-32`.

OOD-stress cases are:

- `random-32-32-10`: small dense random map, high interaction density.
- `maze-128-128-2`: long corridors and topological bottlenecks.
- `warehouse-10-20-10-2-1`: structured congestion and narrow aisles.
- `den312d`: smaller/tighter game map, moderate difficulty.

Using the `wave9_compact` full CSV as the main local full-scale anchor:

| Group | Maps | Flow-Vector Map-Mean Success | SSIL Map-Mean Success | Interpretation |
|---|---|---:|---:|---|
| Topology-proximal / easier | Paris, den520d, empty-48, random-64 | 95.30% | 96.20% | Flow is almost tied with SSIL on easier or structurally forgiving maps |
| OOD-stress / dense or bottleneck | den312d, maze-128, random-32, warehouse | 34.85% | 38.85% | Gap grows on dense coordination, maze, and warehouse-like structures |

The key observation is that flow-vector inference does not fail uniformly. It
generalizes well when the velocity field gives a clear local direction and the
CS-PIBT shield can resolve conflicts. It struggles when success depends on
precise wait decisions, bottleneck negotiation, or dense local coordination.

### With vs Without Coordination-Heavy Maps

To make the coordination story explicit, we can slice the Rishi-8 full eval into
coordination-heavy and non-coordination-heavy subsets. Here, the main

This choice is deliberate:

- `random-32-32-10` is the small dense random map where many agents interact in

This is one of the cleanest narrative findings:

> On the non-coordination-heavy slice, Flow-CS-PIBT is essentially tied with
> SSIL. The SSIL advantage appears primarily on maps that demand heavy
> coordination, especially small dense random maps and maze bottlenecks.

This supports, but does not by itself fully prove, the mechanistic story that
SSIL's discrete action classifier learns coordination and wait behavior more
directly. SSIL is trained end-to-end to output a 5-way action distribution
(move cardinally or wait), so its trunk is optimized for the same discrete
decision that CS-PIBT consumes. The flow model is trained to predict continuous
velocities and only later converts those velocities into discrete action
preferences. That continuous objective works well when the desired motion is
directional and locally clear, but it can blur or under-specify the exact wait
and priority decisions needed in dense local conflicts.

The ablations reinforce this interpretation:

- Direct action-head fixes improved quick eval but did not beat flow-vector
  medium eval, suggesting the issue was not just inference plumbing.
- Discrete-primary training improved `random-32-32-10` substantially in some
  settings, but hurt broader map generalization.
- Tiny custom coordination data with strict flow-only training raised medium
  `random-32-32-10` to 70%, but did not improve overall medium performance
  enough to replace the main flow-vector model.

So the reportable story is not simply "flow cannot coordinate." A more accurate
statement is:

> Flow-vector inference is competitive with SSIL on most non-coordination-heavy
> held-out maps. The remaining performance gap is concentrated in maps where
> success depends on explicit discrete coordination and waiting. This is
> consistent with SSIL's advantage as a discrete action classifier and with the
> flow model's limitation as a continuous velocity predictor whose outputs must
> be converted into discrete CS-PIBT preferences.

The `random-32-32-10` map is the most informative OOD-stress case. On full eval,
flow-vector reaches 68-71% depending on which flow anchor is used, while SSIL is
81%. On medium eval, the gap can look much larger: flow-vector 50% versus SSIL
90%. This explains why quick/medium random-32 numbers have been used as a
diagnostic even though full eval is the final authority.

## Ablation Timeline

### Phase 1: Action-Head Inference Conditioning

Problem: direct action-head inference initially produced 0% success.

Root cause:

1. The action head was trained on noisy flow states `(x_t, t)`.
2. Inference fed it out-of-distribution states such as `(v=0, t=0.5)`.
3. The action head could also learn shortcuts from `v_t`, because `v_t`
   contains information about the target action direction.

Fix:

- Added `--actionHeadConditioning {integrated, zero_t0, zero_t05}` in
  `main_pys/simulator.py`.
- Added `--action-head-conditioning` pass-through in `eval_rishi_paper.py`.
- Integrated the flow ODE at inference to approximate `x_1`, then evaluated the
  action head at high `t`.

Results:

| Variant | Quick Success | Notes |
|---|---:|---|
| Original action-head inference | 0.00% | Fully broken due to train/inference mismatch |
| `head_integrated` | 43.48% | Major recovery from 0% |
| `head_zero_t0` | 0.00% | Confirms zero-state features are out of distribution |

Conclusion: inference conditioning mattered, but fixing it was not enough to
beat flow-vector inference.

### Phase 2: Action-Head Training Distribution

Problem: even with integrated inference conditioning, action-head performance was
still too weak.

Training modes added:

| Mode | Description | Outcome |
|---|---|---|
| `shared` | Original action CE on same noisy forward pass | Shortcut-prone |
| `zero_v` | Train action CE with `v=0, t=0` | Mismatched with integrated inference |
| `both` | Average original and zero-v CE | Improved but still weak |
| `x1_t1` | Train action CE on `(x_1, t=0.99)` | Best match to integrated action-head inference |

Important results:

| Experiment | Setup | Quick | Medium | Notes |
|---|---|---:|---:|---|
| `repair_both` | Action-head repair, mixed CE mode | 47.83% | - | Some recovery but competing objectives |
| `action_head_only_zerov` | Frozen trunk, zero-v action-head training | 0.00% | - | Confirms zero-v is the wrong inference distribution |
| `wave8_head_repair_x1` | Frozen trunk, `x1_t1` action-head-only repair | 69.57% | 62.70% | Quick tied SSIL, but medium was worse than flow-vector |

Interpretation: `x1_t1` fixed the interface problem, but the action head still
read from a trunk optimized primarily for continuous flow prediction. Correcting
the train/inference distribution did not make the direct action head robust.

### Phase 6: Tiny Custom Coordination Data Ablation

This is the newest ablation series. It tests whether a tiny amount of deliberate

GB of preprocessed data.

## Key Findings

1. **The main contribution is still the flow-vector policy.**

   Flow-vector inference is the only learned method in this series with robust
   full-scale performance close to SSIL. It reaches 64.05-64.59% full Rishi-8
   success depending on the checkpoint anchor, while SSIL is 66.43%.

2. **Action-head quick wins did not hold at medium scale.**

   The repaired `x1_t1` action head and the tiny-focus hybrid both reached
   69.57% quick success, but medium eval dropped to 62.70% and 63.78-64.59%.
   This makes quick eval useful only as a smoke test.

3. **The dense random-32 map is the key diagnostic.**

   On medium eval, the flow-vector baseline was 50% on `random-32-32-10`, while
   SSIL was 90%. Several ablations improved this map, but those improvements
   usually came with losses elsewhere.

4. **Discrete pressure helps coordination but hurts broad generalization.**

   Action loss weight 2.0 improved random-32 to 75% at medium but overall fell
   to 60.00%. Hybrid w1.5 gave better overall behavior but did not fix random-32.

5. **Strict flow-only custom-data training produced the cleanest dense-map signal.**

   `flowonly_focus_tiny_h512_l3_epoch_5` reached 70% on random-32 and 80% on
   random-64 using normal flow-vector inference. However, its overall medium
   score was only 62.43%, and additional epochs degraded the result.

6. **Custom data amount and mixture are sensitive.**

   A full custom preprocessed dataset reached 315 GB and was impractical under
   current disk constraints. A 28,935-sample tiny focus set was manageable and
   produced useful diagnostic movement, but not a new best model.

7. **SSIL remains stronger on discrete coordination.**

   SSIL likely benefits from training its trunk end-to-end for discrete action
   cross-entropy. Flow trunks are optimized for continuous velocity prediction,
   and retrofitted or jointly trained action heads have not yet matched SSIL's
   coordination behavior without hurting other maps.

## Interpretation for the Paper / Presentation

The positive story should not be "we beat SSIL." We have not. The positive story
is:

- A continuous rectified-flow GNN policy can serve as a competitive MAPF action
  prior under CS-PIBT.
- The flow-vector model reaches within roughly 2-3 percentage points of SSIL on
  the main Rishi-8 benchmark.
- It matches or beats SSIL on several map types, including random-64 and den312d
  in the main full-eval table.
- Its weaknesses are interpretable: small dense random maps, maze bottlenecks,
  and warehouse-like congestion.
- A detailed ablation series shows that the remaining gap is not merely an
  inference-conditioning bug or action-head interface issue. It is likely tied
  to objective/trunk representation differences between continuous flow matching
  and discrete CE classifier training.

Suggested framing:

> Flow-CS-PIBT demonstrates that continuous flow matching can produce a strong
> MAPF guidance policy for CS-PIBT, approaching the discrete SSIL classifier
> while offering a different continuous generative interface. Our ablations show
> that direct action-head retrofits and discrete-primary hybrids improve some
> dense coordination cases but do not robustly surpass the original flow-vector
> policy, making the flow-only model the central contribution and the hybrid
> experiments diagnostic evidence about the remaining coordination gap.
